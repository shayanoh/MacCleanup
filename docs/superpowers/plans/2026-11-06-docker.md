# Docker screen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Docker page in MacCleanup that lists images, containers, volumes and build cache as one connected tree with exact sizes, dates, layers and read-only file browsing, removes items through Docker's own commands, and trims the Docker VM disk afterwards.

**Architecture:** A new `src/docker/` module turns Docker Engine API JSON (read over Docker Desktop's unix socket with `curl --unix-socket`, through the existing `CommandRunner` so tests use `FakeRunner`) into a model, analyses it (tree, shared/unique/frees, set-wise frees), and a `DockerView` flattens it into lines. A new screen draws those lines with the Explorer's column helpers. Removals are `ReviewCommand`s in the existing shared selection (`App::tool_marks` ids prefixed `docker:`), review and `CommandJob`, so ordering, `y`-only confirm, cancel and failure reporting are reused.

**Tech Stack:** Rust 2024, ratatui 0.30, `serde_json` (already a dependency), `curl` and `docker` CLIs via `CommandRunner`.

**Spec:** `docs/superpowers/specs/2026-11-06-docker-design.md` (also read the parents it names, and `CLAUDE.md`, whose rules apply to every task).

## Global Constraints

- Add dependencies only with `cargo add`; run `cargo fmt`; `cargo clippy --all-targets -- -D warnings` must be clean; `cargo test` green before every commit. Commits need no asking in this repo.
- Nothing slow on the UI thread: every Docker call runs through `bg::Latest`/`bg::Work` or `CommandJob`; a caller that can fire every tick never starts a job while one is `pending`.
- Real Docker commands are never run in tests: `FakeRunner` (unit) or a no-op `CommandRunner` (integration). Anything running the binary sets a throwaway `HOME`.
- Every Docker command pins the context: CLI calls carry `--context=desktop-linux`; API calls use the socket path read from `docker context inspect desktop-linux`.
- Docker removals are irreversible: `y` only (Enter never confirms), no `--force` added on the user's behalf, bulk marks take only dangling images and unused build cache.
- Columns on the Docker page: Name, Size, Frees, Last used, Created (header order = `s` cycle). Explorer and Caches & Projects gain a Modified column at the end of the number columns, before the share bar.
- File names on screen go through `ui::clean`/`fit`/`fit_start`; ASCII fallback and `--no-animation` respected; menu digit is the page's position in `SIDEBAR`; update `README.md` and `CLAUDE.md` in the same change.
- The trim image is built from stdin as `maccleanup/vm-tools`, `FROM alpine:3`, label `com.maccleanup=1`, entrypoint `nsenter -t 1 -m -u -n -i fstrim -v /var/lib/docker`. The number `fstrim -v` prints is never shown as a result.
- Docker's reported `UniqueSize` is not trusted (it can be negative); shared/unique/frees are computed by the app.

## Review Focus

- Docker not installed, daemon stopped, or no `desktop-linux` context: the page says which and offers `r`, nothing crashes, nothing runs on another context.
- An image tag removal where another image shares layers, and a layer shared by two marked images (frees only once all holders are marked).
- A volume or image used by a stopped container, a running container, or a volume shared by two containers (refusal rules, tree placement).
- Names and commands containing control characters, very long build-step commands, and `<none>`/empty tags.
- A trim that frees nothing, fails, or is cancelled; a removal that Docker refuses; quit while a Docker command runs.
